# MCPShield rule catalogue

60 rules · generated by `mcpshield rules --markdown` (v1.1.0).

Scopes: **config** = static config analysis · **agent** = client/agent settings · **live** = requires `--live` · **http** = remote-server probes · **integrity** = lock-file verification.

## MCPS-SEC-001 — Hardcoded secret in server environment

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP01 Token Mismanagement & Secret Exposure · **OWASP Agentic:** ASI03 · **CWE:** CWE-798

A credential is stored as a literal value in the MCP client configuration. Config files are synced, backed up, committed to repositories and readable by every process running as the user — including other MCP servers.

**Remediation:** Reference the secret from the environment or a secret manager (e.g. "${GITHUB_TOKEN}", VS Code "${input:…}" prompts, OS keychain) and rotate the exposed credential.

## MCPS-SEC-002 — Secret passed on the command line

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP01 Token Mismanagement & Secret Exposure · **OWASP Agentic:** ASI03 · **CWE:** CWE-214, CWE-798

A credential appears in the server's command-line arguments. Arguments are visible to every local user via the process list and are frequently written to shell history and logs.

**Remediation:** Pass secrets through environment variables or files with restrictive permissions, never through argv. Rotate the credential.

## MCPS-SEC-003 — Literal credential in HTTP headers

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP01 Token Mismanagement & Secret Exposure, MCP07 Insufficient Authentication & Authorization · **OWASP Agentic:** ASI03 · **CWE:** CWE-798

A remote server's Authorization (or API-key) header contains a literal token in the config file.

**Remediation:** Use OAuth 2.1 as defined by the MCP authorization spec, or reference the token from the environment. Rotate the token.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization>

## MCPS-SEC-004 — Credential embedded in server URL

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP01 Token Mismanagement & Secret Exposure · **OWASP Agentic:** ASI03 · **CWE:** CWE-598

The server URL carries credentials (user:password@host or a token/key query parameter). URLs leak through logs, proxies, browser history and Referer headers.

**Remediation:** Move credentials to an Authorization header or OAuth. Never place tokens or session identifiers in URLs.

## MCPS-SEC-005 — Config file containing secrets is readable by other users

**Default severity:** medium · **Scope:** config · **OWASP MCP:** MCP01 Token Mismanagement & Secret Exposure · **CWE:** CWE-732

The configuration file holds literal credentials and is group- or world-readable.

**Remediation:** chmod 600 the file (or remove the secrets from it).

## MCPS-TRN-001 — Remote MCP server over plaintext HTTP

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **OWASP Agentic:** ASI07 · **CWE:** CWE-319

Traffic — including OAuth tokens, tool arguments and results — travels unencrypted to a non-loopback host.

**Remediation:** Use https:// with a valid certificate (TLS 1.2+, preferably 1.3). Plain http:// is only acceptable for localhost development.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http>

## MCPS-TRN-002 — Deprecated HTTP+SSE transport

**Default severity:** low · **Scope:** config · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization

The HTTP+SSE transport (2024-11-05) is Deprecated under the MCP feature lifecycle policy and may be removed. It lacks the per-request metadata validation of Streamable HTTP.

**Remediation:** Migrate the server and client to Streamable HTTP.

- <https://modelcontextprotocol.io/specification/2026-07-28/changelog>

## MCPS-TRN-003 — Local server bound to all interfaces

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization, MCP09 Shadow MCP Servers · **OWASP Agentic:** ASI03 · **CWE:** CWE-1327

The server is started with a 0.0.0.0/:: bind address, exposing it to the network. Local MCP servers commonly lack authentication; hundreds have been found exposed on the internet.

**Remediation:** Bind local servers to 127.0.0.1 only (spec SHOULD) and require authentication for any network-exposed server.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http>

## MCPS-TRN-004 — TLS certificate verification disabled

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **CWE:** CWE-295

The server environment or arguments disable TLS verification (e.g. NODE_TLS_REJECT_UNAUTHORIZED=0), enabling man-in-the-middle interception of upstream API traffic and credentials.

**Remediation:** Remove the override and trust the proper CA bundle instead (NODE_EXTRA_CA_CERTS / SSL_CERT_FILE).

## MCPS-EXE-001 — Server launched through a shell interpreter

**Default severity:** medium · **Scope:** config · **OWASP MCP:** MCP05 Command Injection & Execution · **OWASP Agentic:** ASI05 · **CWE:** CWE-78

The server is started via 'sh -c', 'bash -c', 'cmd /c' or PowerShell. Shell wrappers hide what actually runs, enable command chaining and are the pattern behind the systemic STDIO command-execution issues reported in 2026.

**Remediation:** Invoke the server binary directly with an argument array. If a wrapper is unavoidable, keep it in a reviewed script file.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices#local-mcp-server-compromise>

## MCPS-EXE-002 — Download-and-execute in server command

**Default severity:** critical · **Scope:** config · **OWASP MCP:** MCP05 Command Injection & Execution, MCP04 Software Supply Chain Attacks & Dependency Tampering · **OWASP Agentic:** ASI05, ASI04 · **CWE:** CWE-494, CWE-78

The launch command fetches remote content and pipes it to an interpreter (curl … | sh, iwr … | iex, base64 -d | sh). Whoever controls that URL controls your machine every time the client starts.

**Remediation:** Install a pinned, verified artifact and run it directly. Remove remote-script execution from MCP configuration.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices#local-mcp-server-compromise>

## MCPS-EXE-003 — Server runs with elevated privileges

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP02 Privilege Escalation via Scope Creep · **OWASP Agentic:** ASI03, ASI05 · **CWE:** CWE-250

The server is launched through sudo/doas/runas or as root inside a container, so any tool-level compromise becomes a host compromise.

**Remediation:** Run MCP servers as an unprivileged user with the minimum filesystem and network access they need.

## MCPS-EXE-004 — Container escape-prone Docker options

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP02 Privilege Escalation via Scope Creep, MCP05 Command Injection & Execution · **OWASP Agentic:** ASI05 · **CWE:** CWE-250, CWE-269

The server container runs with --privileged, host namespaces, dangerous capabilities, the Docker socket, or a host root mount — which removes the isolation the container was supposed to provide.

**Remediation:** Drop --privileged/--cap-add, avoid host networking/PID, never mount /var/run/docker.sock or '/', and mount only the directories required (read-only where possible).

## MCPS-EXE-005 — Inline code evaluation in launch command

**Default severity:** medium · **Scope:** config · **OWASP MCP:** MCP05 Command Injection & Execution · **OWASP Agentic:** ASI05 · **CWE:** CWE-94

The server is started with inline code (node -e, python -c, deno eval). The executed code is not reviewable or versioned.

**Remediation:** Move the code into a versioned, reviewed file or package.

## MCPS-SUP-001 — Unpinned package version

**Default severity:** medium · **Scope:** config · **OWASP MCP:** MCP04 Software Supply Chain Attacks & Dependency Tampering · **OWASP Agentic:** ASI04 · **CWE:** CWE-1357, CWE-494

The server is fetched and executed from a registry without a pinned version (npx/uvx/pipx/docker :latest). A compromised or hijacked release executes automatically on next launch — the delivery mechanism of the postmark-mcp backdoor.

**Remediation:** Pin exact versions (pkg@1.2.3, pkg==1.2.3, image@sha256:…), review upgrades, and prefer a lockfile or internal mirror.

The configuration launches a package that has been identified as malicious.

The package name is one or two characters away from (or an unscoped copy of) a well-known MCP server package.

**Default severity:** medium · **Scope:** config · **OWASP MCP:** MCP04 Software Supply Chain Attacks & Dependency Tampering · **OWASP Agentic:** ASI04 · **CWE:** CWE-494

The server is installed from a git URL, tarball or raw URL rather than a registry release, bypassing registry provenance.

**Remediation:** Install from a registry release with provenance, pin to a commit SHA at minimum, and mirror it internally.

## MCPS-SUP-006 — Package with known advisories used without version pin

**Default severity:** medium · **Scope:** config · **OWASP MCP:** MCP04 Software Supply Chain Attacks & Dependency Tampering · **OWASP Agentic:** ASI04 · **CWE:** CWE-1395

The package has published vulnerabilities in some versions and the configuration does not pin a version, so the installed version cannot be verified from the configuration alone.

**Remediation:** Pin a version at or above the fixed release listed in the advisory.

## MCPS-PRV-001 — Filesystem access scoped to root or home directory

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP02 Privilege Escalation via Scope Creep · **OWASP Agentic:** ASI03, ASI02 · **CWE:** CWE-732

The server is granted the entire filesystem or home directory, which includes SSH keys, cloud credentials, browser profiles and other MCP configs. Prompt-injected agents routinely target these files.

**Remediation:** Grant only the project directories the workflow needs, ideally read-only.

## MCPS-PRV-002 — Credential store exposed to server

**Default severity:** critical · **Scope:** config · **OWASP MCP:** MCP01 Token Mismanagement & Secret Exposure, MCP02 Privilege Escalation via Scope Creep · **OWASP Agentic:** ASI03 · **CWE:** CWE-522

A path such as ~/.ssh, ~/.aws, ~/.kube, ~/.docker or ~/.gnupg is passed to or mounted into the server.

**Remediation:** Remove credential directories from the server's scope. Use short-lived, least-privilege tokens passed via env references.

## MCPS-PRV-003 — Toxic capability combination across configured servers

**Default severity:** high · **Scope:** config · **OWASP MCP:** MCP10 Context Injection & Over-Sharing, MCP06 Prompt Injection via Contextual Payloads · **OWASP Agentic:** ASI01, ASI02 · **CWE:** CWE-200

The same agent is given (1) access to private data, (2) exposure to untrusted content and (3) a way to communicate externally. This 'lethal trifecta' lets a single prompt injection in untrusted content exfiltrate private data.

**Remediation:** Split these capabilities across separate agents/sessions, require human approval for outbound actions, or run MCPShield proxy with an egress policy.

## MCPS-SHD-001 — MCP server not on the approved allowlist

**Default severity:** medium · **Scope:** config · **OWASP MCP:** MCP09 Shadow MCP Servers · **OWASP Agentic:** ASI04

A configured MCP server is not in the organisation's allowlist (shadow MCP).

**Remediation:** Review the server; add it to the allowlist or remove it from the client configuration.

## MCPS-SHD-002 — Same server name points to different targets

**Default severity:** low · **Scope:** config · **OWASP MCP:** MCP09 Shadow MCP Servers

Two configuration files define a server with the same name but different commands/URLs, so which one runs depends on client precedence.

**Remediation:** Give servers unique names and remove stale definitions.

## MCPS-AGT-001 — Project MCP servers auto-approved

**Default severity:** high · **Scope:** agent · **OWASP MCP:** MCP09 Shadow MCP Servers, MCP05 Command Injection & Execution · **OWASP Agentic:** ASI04, ASI05 · **CWE:** CWE-829

'enableAllProjectMcpServers' (Claude Code) or equivalent auto-enables any MCP server defined in a repository's .mcp.json. Cloning a malicious repository then starts attacker-chosen servers without consent (see CVE-2025-59536 / CVE-2026-21852).

**Remediation:** Set it to false and approve project servers individually ('enabledMcpjsonServers'); keep Claude Code updated.

- <https://research.checkpoint.com/2026/rce-and-api-token-exfiltration-through-claude-code-project-files-cve-2025-59536/>

## MCPS-AGT-002 — Repository-defined hooks execute shell commands

**Default severity:** medium · **Scope:** agent · **OWASP MCP:** MCP05 Command Injection & Execution · **OWASP Agentic:** ASI05 · **CWE:** CWE-829

Project-level agent settings define hooks that run shell commands automatically. Hooks in cloned repositories were the code-execution vector in CVE-2025-59536.

**Remediation:** Review every hook command; keep hooks in user-level settings, not in shared repositories.

## MCPS-AGT-003 — Project settings redirect the model API endpoint

**Default severity:** high · **Scope:** agent · **OWASP MCP:** MCP01 Token Mismanagement & Secret Exposure · **OWASP Agentic:** ASI03 · **CWE:** CWE-522

Project settings override ANTHROPIC_BASE_URL / OPENAI_BASE_URL (or similar), which can send API keys and prompts to an attacker-controlled endpoint (CVE-2026-21852 class).

**Remediation:** Remove API endpoint overrides from repository-level settings; set them only in trusted user-level configuration.

## MCPS-AGT-004 — Tool calls auto-approved without human confirmation

**Default severity:** medium · **Scope:** agent · **OWASP MCP:** MCP02 Privilege Escalation via Scope Creep · **OWASP Agentic:** ASI09, ASI02 · **CWE:** CWE-862

The client is configured to run MCP tools without confirmation (e.g. Gemini CLI "trust": true, Cline/Roo "alwaysAllow"/"autoApprove", VS Code chat.tools.autoApprove, Claude Code wildcard mcp__ permissions or bypassPermissions).

**Remediation:** Keep confirmation for tools with side effects; auto-approve only read-only tools you have reviewed.

## MCPS-CFG-001 — Configuration could not be fully parsed

**Default severity:** info · **Scope:** config

Part of the configuration file could not be interpreted; those entries were not assessed.

**Remediation:** Fix the reported entries so they can be scanned.

## MCPS-TOOL-001 — Tool poisoning: instructions embedded in tool description

**Default severity:** critical · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning, MCP06 Prompt Injection via Contextual Payloads · **OWASP Agentic:** ASI01, ASI02 · **CWE:** CWE-1427

The tool description contains language aimed at the model rather than describing the tool (instruction overrides, concealment from the user, exfiltration steps). Clients pass descriptions to the model verbatim, so this executes before the tool is ever called ('line jumping').

**Remediation:** Do not connect this server. Report it to the publisher/registry. Pin reviewed tool definitions with 'mcpshield pin'.

- <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks>

## MCPS-TOOL-002 — Hidden characters in model-visible metadata

**Default severity:** high · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning · **OWASP Agentic:** ASI01 · **CWE:** CWE-1007, CWE-116

Tool/prompt/resource metadata contains invisible Unicode tag characters, zero-width or bidi-override characters, or ANSI escape sequences. These hide content from human reviewers while the model still reads it.

**Remediation:** Reject metadata containing these characters; normalise and display metadata in clients before approval.

## MCPS-TOOL-003 — Full-schema poisoning: injection inside input schema

**Default severity:** critical · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning · **OWASP Agentic:** ASI01 · **CWE:** CWE-1427

Injection language is embedded in the input schema (parameter names, descriptions, titles, defaults or enum values), which models also read. Scanners that only check the description miss this.

**Remediation:** Treat the whole tool definition as untrusted; do not connect the server.

- <https://owasp.org/www-project-mcp-top-10/2025/MCP03-2025%E2%80%93Tool-Poisoning>

## MCPS-TOOL-004 — Parameter designed to capture context or secrets

**Default severity:** high · **Scope:** live · **OWASP MCP:** MCP10 Context Injection & Over-Sharing, MCP03 Tool Poisoning · **OWASP Agentic:** ASI01 · **CWE:** CWE-200

A parameter's name or description asks for conversation history, system prompts, file contents or credentials that the tool's function does not need (the 'sidenote' exfiltration pattern).

**Remediation:** Remove the server or constrain the parameter; audit what has already been sent.

## MCPS-TOOL-005 — Cross-server tool shadowing

**Default severity:** high · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning · **OWASP Agentic:** ASI01, ASI07 · **CWE:** CWE-1427

A tool's metadata references tools that belong to a different server, attempting to change how those tools behave (e.g. redirecting e-mail recipients).

**Remediation:** Isolate untrusted servers from sensitive ones and remove the offending server.

## MCPS-TOOL-006 — Tool name collision across servers

**Default severity:** medium · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning, MCP09 Shadow MCP Servers · **OWASP Agentic:** ASI02

Two servers expose tools with the same name. Clients may resolve calls to the wrong server, and a malicious server can deliberately collide with a trusted tool.

**Remediation:** Rename or namespace the tools, or disable one of the servers.

## MCPS-TOOL-007 — External URL or e-mail address in tool metadata

**Default severity:** medium · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning, MCP10 Context Injection & Over-Sharing · **OWASP Agentic:** ASI01

Tool metadata references an external URL or e-mail address — a common exfiltration destination in poisoned tools.

**Remediation:** Confirm the destination is legitimate and expected for this tool.

## MCPS-TOOL-008 — Misleading tool annotations

**Default severity:** medium · **Scope:** live · **OWASP MCP:** MCP02 Privilege Escalation via Scope Creep · **OWASP Agentic:** ASI09

The tool claims readOnlyHint / non-destructive behaviour but its name or schema indicates writes, deletion or execution. Clients that auto-approve 'read-only' tools can be tricked into running it.

**Remediation:** Correct the annotations. Clients must treat annotations from untrusted servers as hints only.

## MCPS-TOOL-009 — Unconstrained high-risk parameter

**Default severity:** low · **Scope:** live · **OWASP MCP:** MCP05 Command Injection & Execution · **OWASP Agentic:** ASI02 · **CWE:** CWE-20

A parameter that carries a shell command, file path, URL or query is a free-form string with no pattern, enum or length limit.

**Remediation:** Constrain the schema (enum/pattern/maxLength, additionalProperties: false) and validate server-side.

## MCPS-TOOL-010 — Oversized tool description

**Default severity:** low · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning

Very long descriptions consume context and are a common place to hide instructions.

**Remediation:** Keep descriptions concise (< 1,000 characters) and factual.

## MCPS-TOOL-011 — Invalid x-mcp-header annotation

**Default severity:** medium · **Scope:** live · **OWASP MCP:** MCP05 Command Injection & Execution · **CWE:** CWE-113

An inputSchema property uses 'x-mcp-header' in a way the 2026-07-28 spec forbids (invalid header token, CR/LF, duplicate, non-primitive or not statically reachable). Conforming clients must drop the tool; lax clients may allow header injection.

**Remediation:** Fix the annotation per the Streamable HTTP 'Custom Headers from Tool Parameters' rules.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http>

## MCPS-TOOL-012 — Lethal trifecta within a single server

**Default severity:** high · **Scope:** live · **OWASP MCP:** MCP10 Context Injection & Over-Sharing, MCP06 Prompt Injection via Contextual Payloads · **OWASP Agentic:** ASI01, ASI02 · **CWE:** CWE-200

One server's tools can read private data, ingest untrusted content and communicate externally. A prompt injection delivered through the untrusted content can exfiltrate the private data without any other server involved.

**Remediation:** Split capabilities, require approval for outbound tools, or enforce an egress policy with 'mcpshield proxy'.

## MCPS-TOOL-013 — Excessive number of tools

**Default severity:** low · **Scope:** live · **OWASP MCP:** MCP02 Privilege Escalation via Scope Creep · **OWASP Agentic:** ASI02

The server exposes a very large tool surface, which increases mis-selection risk and the chance of a dangerous tool being invoked.

**Remediation:** Expose only the tools the workflow needs (most clients support per-tool disabling).

## MCPS-TOOL-014 — Injection language in server instructions

**Default severity:** high · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning, MCP06 Prompt Injection via Contextual Payloads · **OWASP Agentic:** ASI01 · **CWE:** CWE-1427

The 'instructions' returned by the server (injected into the system prompt by many clients) contain manipulative or hidden content.

**Remediation:** Do not connect the server; clients should display server instructions to users.

## MCPS-TOOL-015 — Injection language in prompt or resource metadata

**Default severity:** high · **Scope:** live · **OWASP MCP:** MCP06 Prompt Injection via Contextual Payloads, MCP03 Tool Poisoning · **OWASP Agentic:** ASI01, ASI06 · **CWE:** CWE-1427

Prompt templates or resource descriptions advertised by the server contain injection language or hidden characters.

**Remediation:** Review the server; treat its prompts/resources as untrusted input.

## MCPS-TOOL-016 — Tool definition changed since it was pinned (rug pull)

**Default severity:** critical · **Scope:** integrity · **OWASP MCP:** MCP03 Tool Poisoning, MCP04 Software Supply Chain Attacks & Dependency Tampering · **OWASP Agentic:** ASI04 · **CWE:** CWE-494

A tool's definition (description or schema) differs from the reviewed version recorded in mcpshield.lock. Silent redefinition after approval is the 'rug pull' attack.

**Remediation:** Review the diff. If unexpected, disconnect the server and rotate credentials it could access. Re-pin only after review.

## MCPS-TOOL-017 — Tool added or removed since pinning

**Default severity:** medium · **Scope:** integrity · **OWASP MCP:** MCP03 Tool Poisoning · **OWASP Agentic:** ASI04

The server's tool list differs from the pinned inventory.

**Remediation:** Review the new tools before use and re-pin.

## MCPS-TOOL-018 — Tool name imitates another server's namespace

**Default severity:** low · **Scope:** live · **OWASP MCP:** MCP03 Tool Poisoning · **OWASP Agentic:** ASI09

The tool name contains another well-known server's name or a prefix used for namespacing (e.g. 'github_', 'slack_') while the server itself is different, which can confuse users approving calls.

**Remediation:** Rename the tool to reflect the server that implements it.

## MCPS-HTTP-001 — Remote MCP server accepts unauthenticated requests

**Default severity:** high · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **OWASP Agentic:** ASI03 · **CWE:** CWE-306

The server listed its tools to an anonymous client. Anyone who can reach the endpoint can invoke them.

**Remediation:** Require OAuth 2.1 per the MCP authorization spec (or at minimum a strong bearer token) for every request.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization>

## MCPS-HTTP-002 — Origin header not validated (DNS rebinding)

**Default severity:** high · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **OWASP Agentic:** ASI03 · **CWE:** CWE-350, CWE-346

The server processed a request carrying a foreign Origin header. The spec requires servers to validate Origin and reply 403 to invalid origins; without it, any web page the user visits can drive a local MCP server via DNS rebinding.

**Remediation:** Validate Origin against an allowlist and return 403 otherwise; bind local servers to 127.0.0.1; upgrade SDKs (TypeScript ≥1.24.0, Python ≥1.23.0 enable protection by default).

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http>

## MCPS-HTTP-003 — No OAuth Protected Resource Metadata

**Default severity:** medium · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **CWE:** CWE-287

The server requires authorization but does not advertise RFC 9728 Protected Resource Metadata (WWW-Authenticate resource_metadata or /.well-known/oauth-protected-resource), so clients cannot discover the authorization server safely.

**Remediation:** Serve Protected Resource Metadata and include resource_metadata in 401 WWW-Authenticate challenges.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization>

## MCPS-HTTP-004 — Authorization server does not support PKCE S256

**Default severity:** high · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **CWE:** CWE-287

The authorization server metadata does not list S256 in code_challenge_methods_supported. MCP clients MUST use PKCE with S256.

**Remediation:** Enable PKCE (S256) on the authorization server.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization>

## MCPS-HTTP-005 — Authorization metadata points to insecure or internal endpoints

**Default severity:** high · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **OWASP Agentic:** ASI03 · **CWE:** CWE-918

OAuth metadata advertised by the server references http:// endpoints, private/link-local IPs or non-web schemes. A malicious server can use this to make clients perform SSRF (e.g. cloud metadata at 169.254.169.254) or execute URLs (CVE-2025-6514).

**Remediation:** Use https:// public endpoints only. Clients should block private ranges and non-http(s) schemes.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices#server-side-request-forgery-ssrf>

## MCPS-HTTP-006 — Permissive CORS policy

**Default severity:** medium · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **CWE:** CWE-942

The server reflects arbitrary origins or allows '*' — letting any website issue cross-origin requests to it.

**Remediation:** Return CORS headers only for trusted origins; never combine wildcard origins with credentials.

## MCPS-HTTP-007 — TLS configuration weakness

**Default severity:** high · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **CWE:** CWE-295, CWE-326

The server's TLS certificate failed verification or a deprecated protocol version was negotiated.

**Remediation:** Deploy a valid certificate from a trusted CA and allow only TLS 1.2+.

## MCPS-HTTP-008 — Weak legacy session identifiers

**Default severity:** medium · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization · **CWE:** CWE-330, CWE-384

The server issues Mcp-Session-Id values that are short or predictable. In legacy (≤2025-11-25) Streamable HTTP, session IDs must be cryptographically random and never used for authentication.

**Remediation:** Use ≥128-bit random session IDs, bind them to the authenticated user, or migrate to the stateless 2026-07-28 protocol.

## MCPS-CAP-002 — Server does not support the current MCP protocol revision

**Default severity:** info · **Scope:** live

The server only speaks an initialize-based (legacy) protocol revision. Newer clients will fall back or fail.

**Remediation:** Upgrade the server SDK to a release supporting protocol 2026-07-28.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning>

## MCPS-HTTP-010 — Verbose error disclosure

**Default severity:** low · **Scope:** http · **OWASP MCP:** MCP08 Lack of Audit and Telemetry · **CWE:** CWE-209

Malformed input produced stack traces or internal paths in the response.

**Remediation:** Return generic JSON-RPC errors and log details server-side.

## MCPS-HTTP-011 — Authorization server does not advertise RFC 9207 'iss' support

**Default severity:** low · **Scope:** http · **OWASP MCP:** MCP07 Insufficient Authentication & Authorization

Without the 'iss' authorization-response parameter, clients cannot defend against OAuth mix-up attacks, which the 2026-07-28 spec addresses by requiring clients to validate 'iss' when present.

**Remediation:** Enable authorization_response_iss_parameter_supported on the authorization server.

- <https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices#mix-up-attacks>

## MCPS-CAP-001 — Server relies on deprecated client features

**Default severity:** info · **Scope:** live · **OWASP MCP:** MCP06 Prompt Injection via Contextual Payloads · **OWASP Agentic:** ASI01

The server uses Sampling, Roots or Logging, which the 2026-07-28 spec deprecates. Sampling in particular lets a server ask the client's model to generate content, a known vector for covert prompt injection and resource abuse.

**Remediation:** Migrate away from deprecated features; clients should require user approval for every sampling request.
